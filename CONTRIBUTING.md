# Contributing to RouterChat

Thank you for your interest in contributing to RouterChat!

## Bugs

Open a [GitHub issue](https://github.com/echo1097/routerchat/issues) with as much detail as you can so I can reproduce and fix it. [SUPPORT.md](SUPPORT.md#what-to-include-in-an-issue) lists what to include. 

Never report a security issue publicly. Follow [SECURITY.md](SECURITY.md).

## Feedback

Use the **Feedback** button at the bottom of the sidebar, or fill out [this form](https://forms.gle/gTth2TcXLYAArvGm6).

## What gets merged

I keep RouterChat simple on purpose, so most pull requests fall into one of these two lists.

**Welcome**

- **Bug fixes.** Link the issue and clearly state what was fixed.
- **Significant new features.** A feature has to add something a lot of users would notice and want. Open an issue first so we can agree on it before you build it.
- **Documentation fixes.** Corrections and clearer explanations.

**Not accepted**

- **Refactors.** No restructuring, renaming, reformatting, or cleanup of code that already works. 
- **Small or niche features.** If it only helps a few people or only changes a minor detail, it will not be merged.
- **New dependencies without a strong reason.**
- **AI slop.** If you use AI, review and clean up the code yourself and say how you used it.

## Opening a pull request

- Follow the [developer guide](docs/developer.md) to run RouterChat from source.
- Run the [tests](docs/developer.md#running-tests) and ensure they all pass before opening the PR.
- Limit a pull request to one change, and say what it does and why.
